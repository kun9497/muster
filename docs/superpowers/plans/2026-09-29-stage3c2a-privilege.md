# Stage 3C-2a — Privilege Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship spec 3C-2a — the walk's capability and ACL pass on a `ReadDir` that can read an executable's attributes, three extended collectors (`accounts`, the sudo reader of `files`, `walk`), three new collectors (`units`, `sshkeys`, `privilege`), nineteen registry keys and eight controls of category `beyond` — so a default `check` says who holds root's power without being root: an undeclared file capability, a root service's executable a non-root user can rewrite, an `ld.so.preload` entry, a runtime socket's group, passwordless `ALL` in sudoers, an account the inactivity policy does not cover, root's authorized keys, and weak SSH keys.

**Architecture:** One read primitive grows — `Access.ReadDir` takes `ReadDirOptions{Xattrs: true}` and, for the walk alone, opens each executable from the still-open directory fd, `fstat`-checks it and reads two named xattrs onto the `DirEntry` — and everything else is collectors writing envelopes through the existing `collect.Builder` seams: the walk's `findingLists`/`addRow`/`listCaps`/join machinery gains two lists and one declaration source per family (rpm `%{FILECAPS}`, dpkg `postinst`); `accounts` derives a judged subset of its passwd/shadow rows and decodes `lastlog` records; the sudo chain scan that already walks `/etc/sudoers` and its drop-ins parses aliases and user specifications on the same pass; `units`, `sshkeys` and `privilege` are `register.go`-style collectors with exact `Reads`, one fixed command among them, and capped, sorted, fully-populated rows. Controls are plain `checks` with the loader's grammar (`none` always with a `where`; scalar lists without `field`); the evaluator is untouched.

**Tech Stack:** Go 1.25, `golang.org/x/sys/unix`, `gopkg.in/yaml.v3`, the existing `collect.Access` / `Builder` / `Guard` / `writePermFacts` / `permRow` / `readErrorEnv` / `globReadError` / `commandFailure` / `capRows` / `sourceRaw` / `decodeACL` / `interactive` / `parsePasswd` / `parseGroup` / `linkTarget` seams, the 3F gates (fixture harness, mutation test, fuzz inventory, oracles, examples), GitHub Actions. No new dependency (D28); no sqlite.

**Spec:** `docs/superpowers/specs/2026-09-29-stage3c2a-privilege-design.md` (P-1…P-12; §3 facts, §4 controls, §5 environments, §6 tests/CI/documents, §7 not a fact, §8 parked), committed at `8e3cbf6` with the two fresh reviews folded and corrected at `bd640b4` from this plan's format research (V-1…V-8 below). - **V-40 (postinst forms; ACL widens).** (a) `NAME=$(dpkg-divert --truename <path>)` is a fourth recognised `setcap` form: the literal path inside is the declared path, and only this form may match a diverted file (`iputils-ping`'s `PROGRAM`). (b) `aclWidens` compares a named entry's effective permissions (mask applied) against the owning group's `group::` entry — with named entries the mode's group class IS the mask, so "beyond the mode" means beyond the group entry (`acl(5)`). A 3-entry ACL is folded into the mode by the kernel and stores no xattr, so the opt-out test uses a 5-entry ACL.
- **V-41 (resolution budgets).** Alias expansion is capped at 65536 members and 65536 rows per resolution; anything past a budget is `resolved: false` and the leaf reads `absent`, never a partial answer (the review found a 31 KB file allocating 9 GB under the plan's expansion-counting cap).
- **V-42 / V-43 (comment lexing).** A sudoers line is classified before it is joined: a comment line ends at its newline whatever it ends with (a `#…\` comment used to swallow the next rule — a false PASS), and a comment reached while a line is being joined closes that line, as sudo's lexer reads `\`-newline as a blank and then the comment to its end. A `sha224:`…`sha512:` digest stays one word with its command; aliases resolve after every file of the chain was read (forward references count).
- **V-44 (the declared executable set).** `unitExecReads` gains `/usr/share/*/*` and `/usr/share/*/*/*`: stock Ubuntu runs `unattended-upgrade-shutdown` from `/usr/share/unattended-upgrades/`, and a stock host must not read MANUAL. `/run/*` agents (LXD's `lxd-agent`) and `/var/lib/*` binaries stay outside the set: the row is `stat_status: undeclared` and `units.exec_writable` is `absent` naming the path (MANUAL) — an LXD guest reads MANUAL, said in the spec.
- **V-45 (merged-`/usr` aliases).** `/bin`, `/sbin`, `/lib`, `/lib64` are resolved through their link into `/usr`; the row records `stat_path` and `stat_status` (`ok`, `undeclared`, `denied`, `error`).
- **V-46 (`why: parent_writable`).** An executable whose parent directory is not owned by uid 0 or is group/other-writable is a `units.exec_writable` row (`ReadMeta.ParentUntrusted`); Debian's `root:staff` 2775 `/usr/local/*` reads FAIL truthfully. A denied parent cannot false-FAIL.
- **V-47 (linked and missing units).** A linked unit (`unit_file: symlink` outside the two systemd trees) or an ACTIVE unit whose file no tree holds makes `units.exec_writable` `absent` naming the unit (what runs is unknown → MANUAL); an enabled-only dangling `.wants` link runs nothing and stays merely `exec_unresolved`. A lone `;` word in an `Exec*=` value separates commands (`\;` is a literal argument), one exec row per command. A symlinked executable is judged one hop through its target when the target is declared. A size-0 unit file is a systemd mask. `User=%i` is substituted from the instance name; glob metacharacters in unit names are escaped.
- **V-48 (`rsa-sha2-*` words).** `rsa-sha2-256` / `rsa-sha2-512` type words carry an `ssh-rsa` blob and are the same RSA key to sshd, so they are decoded and judged as RSA (a literal V-8 would let a weak key PASS). Certificates keep V-8 (bits 0, whole-blob fingerprint, unjudged; the oracle skips them). An empty modulus is `unparsed`, never a bits-0 row; trailing blob bytes are `unparsed`; a file two accounts share is listed once under the first account by name.
- **V-49 (seed key bodies).** The four public-key bodies in the fixtures and fuzz seeds (the all-zero synthetic vector and three throw-away keys whose private halves were deleted) are exact-literal allowlist entries in `.gitleaks.toml` under `ssh-public-key-material` with the reason beside them — never a path allowlist.
- **V-50 (symlinked key files).** A symlinked `authorized_keys` or `.ssh` path, which sshd follows and muster does not, is a row `unfollowed: true` with the reason, and the three counts are `absent` naming the path → MANUAL (the J-40 shape), never `error`. An untrusted `/etc/shells` (unreadable or the libc fallback) puts its status on the three counts.
- **V-51 (socket rows).** `privilege.runtime_sockets` rows gain `kind`, `owner_nonroot` and `acl_present`; `container_runtime_access` has four clauses (`other_writable`, `owner_nonroot`, `acl_present` each `none … eq true`, plus the member `not_in` clause): an ACL entry or a non-root owner grants the API to someone no member row names. `runtime_group_members` is capped at 2000 rows (V-12 addendum); an unreadable `/etc/passwd` degrades that leaf alone (the socket rows' `group` comes from `/etc/group`).
- **V-52 (socket xattrs).** A unix socket cannot be opened `O_RDONLY` (ENXIO), so for `S_IFSOCK` only the xattr reads fall back to an `O_PATH` fd opened through the same no-follow primitive and read via `/proc/self/fd/N` — the already-open inode, never the path again. The re-review confirmed the primitive cannot follow a link.
- **V-53 (xattr error after stat).** After a successful stat, any xattr error (including ENOENT/ENOTDIR from a raced path) is the leaf's `error`, never "not there".
