# Stage 3C-2a — Privilege Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship spec 3C-2a — the walk's capability and ACL pass on a `ReadDir` that can read an executable's attributes, three extended collectors (`accounts`, the sudo reader of `files`, `walk`), three new collectors (`units`, `sshkeys`, `privilege`), nineteen registry keys and eight controls of category `beyond` — so a default `check` says who holds root's power without being root: an undeclared file capability, a root service's executable a non-root user can rewrite, an `ld.so.preload` entry, a runtime socket's group, passwordless `ALL` in sudoers, an account the inactivity policy does not cover, root's authorized keys, and weak SSH keys.

**Architecture:** One read primitive grows — `Access.ReadDir` takes `ReadDirOptions{Xattrs: true}` and, for the walk alone, opens each executable from the still-open directory fd, `fstat`-checks it and reads two named xattrs onto the `DirEntry` — and everything else is collectors writing envelopes through the existing `collect.Builder` seams: the walk's `findingLists`/`addRow`/`listCaps`/join machinery gains two lists and one declaration source per family (rpm `%{FILECAPS}`, dpkg `postinst`); `accounts` derives a judged subset of its passwd/shadow rows and decodes `lastlog` records; the sudo chain scan that already walks `/etc/sudoers` and its drop-ins parses aliases and user specifications on the same pass; `units`, `sshkeys` and `privilege` are `register.go`-style collectors with exact `Reads`, one fixed command among them, and capped, sorted, fully-populated rows. Controls are plain `checks` with the loader's grammar (`none` always with a `where`; scalar lists without `field`); the evaluator is untouched.

**Tech Stack:** Go 1.25, `golang.org/x/sys/unix`, `gopkg.in/yaml.v3`, the existing `collect.Access` / `Builder` / `Guard` / `writePermFacts` / `permRow` / `readErrorEnv` / `globReadError` / `commandFailure` / `capRows` / `sourceRaw` / `decodeACL` / `interactive` / `parsePasswd` / `parseGroup` / `linkTarget` seams, the 3F gates (fixture harness, mutation test, fuzz inventory, oracles, examples), GitHub Actions. No new dependency (D28); no sqlite.

**Spec:** `docs/superpowers/specs/2026-09-29-stage3c2a-privilege-design.md` (P-1…P-12; §3 facts, §4 controls, §5 environments, §6 tests/CI/documents, §7 not a fact, §8 parked), committed at `8e3cbf6` with the two fresh reviews folded and corrected at `bd640b4` from this plan's format research (V-1…V-8 below). - **Ruling V-1 (lastlog record size, corrects spec P-1's first draft).** The record is 292 bytes where glibc's `__WORDSIZE_TIME64_COMPAT32` is set — `amd64`, `386`, `arm`, `ppc64le`, `ppc64`, `riscv64`, `mips64`, `mips64le` — and 296 on `arm64`, `s390x` and `loong64`; `ll_time` is read as an unsigned 32-bit (glibc ≥ 2.40 declares it `__uint32_t`) or a signed 64-bit; byte order is the host's (s390x is big-endian). `lastlogRecordSize()` switches on `runtime.GOARCH` with 292 as the default for an unknown arch, and the leaf's reason names the size.
